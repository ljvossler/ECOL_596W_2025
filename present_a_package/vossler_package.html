An Overview of ParallelStructure

Introduction

When performing population genetic analyses, a common step is to estimate the extent of population structuring between samples in your dataset. One of the first programs widely used to accomplish this is STRUCTURE (https://doi.org/10.1093/genetics/155.2.945). Although an assortment of other programs have been developed that either improve output accuracy or computational efficiency, STRUCTURE is still widely used in preliminary population structure tests and continues to serve as a reference for researchers building/using newer programs.

One of the early disadvantages of STRUCTURE was that it was pretty slow and computationally inefficient. The R package outlined here, ParallelStructure, provides an R-based framework for running STRUCTURE across multiple CPU cores, speeding up analysis.

Installing STRUCTURE

STRUCTURE can be installed on your local device or the UA HPC from here: https://web.stanford.edu/group/pritchardlab/structure.html

I recommend you install the package without the Java front end. This is a cross-platform installation process that also avoids the need to install extra software. Move the zipped folder into your preferred directory (optimally to one seen by your current R environment) and extract its contents. All contents will be found in the ‘console/’ folder.

Installing ParallelStructure

Next we need to install ParallelStructure. Use the following code for a cross-platform way to install from the R-Forge repo.

Now we can begin importing the library and setting up our output directory.

library(ParallelStructure)

system('mkdir structure_results')

Understanding our Input Files

ParallelStructure requires two input data files in a custom format unique to STRUCTURE. The example data provided demonstrates what they should look like.

# Loading in example data and writing to files
data <- data("structure_data")
data(structure_data)
data(structure_jobs)

write(t(structure_jobs),ncol=length(structure_jobs[1,]),file='joblist1.txt')
write(t(structure_data),ncol=length(structure_data[1,]),file='example_data.txt')

For a deeper dive into the specifics of how to format your genotype data, you should refer to section 2 of the STRUCTURE documentation where it explains it in detail.

But essentially, we can see that our data should consist of a 2-D matrix showing individuals in rows and locus data in columns. So each row stores the genotype data at specific loci for a given individual. The allele data is stored as unique number values.

Note that STRUCTURE can accept either individual genotype data stored in:

  • A single row (where every set of two columns represents alleles present at a given locus in a diploid individual)

  • Two rows (as shown in the example data above)

structure_jobs is an input unique to ParallelStructure and is what allows for performing multiple jobs with differing parameters, population subsets, and iterations within the same run (rather than needing to update your parameters and data files constantly between runs). Each row stores parameters for a single run.

Running ParallelStructure

Our analysis can now be conveniently performed by calling a single function. and setting a few required/useful parameters (ie: the path to STRUCTURE executable, joblist, datafile, etc.) Though not required, I recommend including printqhat=1 to automatically generate graphical outputs.

parallel_structure(structure_path=‘console/’,joblist=‘joblist1.txt’,n_cpu=4,

infile=‘example_data.txt’,outpath=‘structure_results/’,

numinds=987,numloci=9,printqhat=1)

parallel_structure(structure_path='console/',joblist='joblist1.txt',n_cpu=4,
              infile='example_data.txt',outpath='structure_results/',
              numinds=987,numloci=9,printqhat=1)

NOTE: ParallelStructure has two functions that perform the same task of running STRUCTURE across multiple CPU cores. However, each function performs this task differently behind the scenes. Here I demonstrate the use of the parallel_structure() function, which relies on the parallel_package to perform parallel computing. This package is included in all recent Base R installations, so I recommend using it for this reason.

However, depending on your OS and software needs, you may want/need to explore MPI_structure() which instead relies on the RMPI package for parallelization. The use of this function is the same as parallel_structure(), but you will need to install/set-up RMPI yourself.

Pros/Cons of ParallelStructure

This R-package is fairly limited in scope due to it relying on old pop-structure software that has since been broadly superseded by newer, more accurate methods that also have their own native improvements to computational efficiency.

However, this package can be extremely useful for performing preliminary analyses in a broader popgen project, especially for users less comfortable with coding or running scripts in a command-line environment. It also greatly speeds up the process of setting up multiple runs due to both its submission of many jobs at once and its parallelization capability.
